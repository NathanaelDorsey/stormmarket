## Story: ProductRepository stock methods return Result<Integer, StockError>

**Vertical Slice:** Changes the five stock-modifying query methods in ProductRepository to return `Result<Integer, StockError>` (or `Result<Void, StockError>` for void methods) instead of raw `int`/`void`. Callers must handle the Result to determine success/failure.

### Acceptance Criteria
- [ ] `reserveStock` returns `Result<Integer, StockError>` — `Ok(rowsUpdated)` on success, `Err(StockError.RESERVATION_FAILED)` when 0 rows updated
- [ ] `deductStock` returns `Result<Integer, StockError>` — `Ok(rowsUpdated)` on success, `Err(StockError.DEDUCT_FAILED)` when 0 rows updated
- [ ] `captureStock` returns `Result<Integer, StockError>` — `Ok(rowsUpdated)` on success, `Err(StockError.CAPTURE_FAILED)` when 0 rows updated
- [ ] `restoreStock` returns `Result<Void, StockError>` — `Ok(null)` on success (always succeeds if product exists)
- [ ] `releaseReservedStock` returns `Result<Void, StockError>` — `Ok(null)` on success (always succeeds if product exists)
- [ ] Methods remain `@Modifying` `@Query` annotations unchanged
- [ ] No changes to SQL queries — only return type and result wrapping
- [ ] `ProductRepository` interface compiles without errors

### Technical Notes
- For `restoreStock` and `releaseReservedStock`, the current queries don't have a WHERE condition that can fail (they always update if product exists). Return `Ok(null)` unconditionally since the query executes.
- For `reserveStock`, `deductStock`, `captureStock`: the `@Query` returns `int` (rows updated). Wrap: if `rows > 0` return `Ok(rows)`, else return appropriate `Err(StockError.XXX)`.
- Since this is an interface, the implementation is generated by Spring Data JPA. The return type change is compatible.
- Import `Result`, `Ok`, `Err` from `common.exception`
- Import `StockError` from `product` package
