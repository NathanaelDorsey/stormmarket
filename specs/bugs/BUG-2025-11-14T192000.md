# BUG-2025-11-14T192000: Postman Collection Run Fails - Request URL Empty

## Problem

Running the Postman collection `Storm_Market_API.json` fails for all 22 requests with:
- `runtime: request url is empty` - All requests have empty URLs at runtime
- Test script errors: `Cannot read properties of undefined (reading 'length')`
- Auth flow fails: `getaddrinfo EAI_AGAIN undefined` - DNS resolution fails because URL is undefined
- JSON parsing fails: `"undefined" is not valid JSON`

**Actual behavior**: Collection runs but every request URL resolves to empty/undefined
**Expected behavior**: Requests should resolve `{{baseUrl}}` variable and execute against `http://localhost:8080`

**Reproduction steps**:
1. Run: `postman collection run ./postman/collections/Storm_Market_API.json --env-var "baseUrl=http://localhost:8080" --env-var "authToken=<token>"`
2. Observe all 22 requests fail with "runtime: request url is empty"

**Security impact**: NONE - This is a test infrastructure issue, no production security exploit path.

## Root Cause Analysis

### Phase 1: Reproduce

**Environment**: 
- Postman CLI v1.89.0
- Collection: `postman/collections/Storm_Market_API.json` (v2.1.0 schema)
- Variables passed via `--env-var`: `baseUrl=http://localhost:8080`, `authToken=<token>`
- No environment file in `postman/environments/`

**Logs captured**: All 22 requests fail with identical pattern - URL resolution fails, test scripts fail on undefined response body.

### Phase 2: Isolate

**Code path analysis**:
- YAML source files (in `postman/collections/Storm Market API/`) use `{{baseUrl}}/v1/...` variable templates correctly
- Compiled JSON collection (`postman/collections/Storm_Market_API.json`) has hardcoded URLs: `"raw": "http://localhost:8080/v1/products/admin/1"` instead of `"raw": "{{baseUrl}}/v1/products/admin/1"`
- Collection `variable` section only defines `authToken`, missing `baseUrl` variable definition
- Scripts use `pm.variables.get('baseUrl')` which returns undefined

### Phase 3: Hypothesize

**Hypothesis 1 (Primary)**: The compiled JSON collection has hardcoded `http://localhost:8080` URLs instead of `{{baseUrl}}` variable templates. The YAML source files use `{{baseUrl}}` but the JSON compilation process replaced them with hardcoded values.

**Hypothesis 2**: The `baseUrl` variable is missing from the collection's variable section, so even if templates were present, they wouldn't resolve.

### Phase 4: Verify

**Confirmed**: Both hypotheses are true.
- JSON has `"raw": "http://localhost:8080/v1/products/admin/1"` (hardcoded)
- YAML has `url: "{{baseUrl}}/v1/products/admin/1"` (template)
- Collection variables only contain `authToken`, no `baseUrl`

**Root cause**: The JSON collection file was generated/compiled with hardcoded localhost URLs instead of preserving the variable templates from YAML source. Additionally, the collection lacks a `baseUrl` variable definition.

**Risk level**: Low - This is a test infrastructure/configuration issue, not application code.
